**Step 5 — src/poller.rs: Apply parity from config in `ModbusPoller::new`** (per D-10)

Change the serial port builder to apply parity:

OLD:
```rust
let builder = tokio_serial::new(&serial.port, serial.baud_rate);
let port = SerialStream::open(&builder)
```

NEW:
```rust
let parity = match serial.parity.as_deref().unwrap_or("N").to_uppercase().as_str() {
    "E" => tokio_serial::Parity::Even,
    "O" => tokio_serial::Parity::Odd,
    _ => tokio_serial::Parity::None,  // "N" or any default
};
let builder = tokio_serial::new(&serial.port, serial.baud_rate)
    .parity(parity);
let port = SerialStream::open(&builder)
```

Note: The `_` arm defaults to `None` (no parity). Invalid values are already rejected by `validate_config` before `ModbusPoller::new` is called, so this is a safe fallback.

# USB-RS485 adapter → /dev/ttyRS485 stable symlink
#
# USAGE NOTES:
#
# 1. This rule matches ANY USB serial adapter on the tty subsystem.
#    If you have multiple USB serial devices, add VID/PID to pin the
#    symlink to a specific adapter:
#
#       udevadm info -a -n /dev/ttyUSB0 | grep -E 'idVendor|idProduct'
#
#    Then add to the rule below:
#       ATTRS{idVendor}=="1a86", ATTRS{idProduct}=="7523",
#    (example values for CH340; yours will differ)
#
# 2. Test without reboot after editing this file:
#       sudo udevadm control --reload-rules
#       sudo udevadm trigger
#       ls -la /dev/ttyRS485   # symlink should appear
#
# 3. Common USB-RS485 chip drivers (for reference only — rule is driver-agnostic):
#       cp210x   — SiLabs CP2102/CP2104 (most common cheap adapters)
#       ch341    — CH340 / CH341 chips
#       ftdi_sio — FTDI FT232R / FT2232 chips
#
# Driver-agnostic rule — works with any USB-RS485 adapter chip.
# Add ATTRS{idVendor}=="XXXX", ATTRS{idProduct}=="XXXX" for precision
# if multiple USB serial devices are connected.
