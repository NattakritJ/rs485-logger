<objective>
Decouple InfluxDB HTTP writes from the Modbus poll loop to eliminate the ~630ms-per-device sequential write bottleneck.

Purpose: The poll loop currently awaits each InfluxDB write before polling the next device. With 5 devices × ~630ms HTTP latency, this adds ~3.15s to every cycle. After this change, writes happen concurrently via `tokio::spawn` and the poll loop only blocks on Modbus reads (~60ms + 30ms IFD per device = ~450ms total).

Output: Modified `src/influx.rs` (Clone derive) and `src/main.rs` (fire-and-forget writes, Arc<AtomicBool> health tracking).
</objective>

**Step 3 — src/main.rs: Replace the synchronous `writer.write(&reading).await` block with `tokio::spawn`** (per D-01, D-02, D-03, D-05, D-07, D-08)

In the poll loop tick arm (inside `Ok(reading) =>` branch), replace the entire InfluxDB write block:

OLD (lines 311-323):
```rust
if let Err(e) = writer.write(&reading).await {
    if influx_healthy {
        tracing::warn!(
            device = %device.name,
            error = %e,
            "InfluxDB write failed — suppressing further warnings until restored"
        );
        influx_healthy = false;
    }
} else if !influx_healthy {
    tracing::info!("InfluxDB connection restored");
    influx_healthy = true;
}
```

NEW:
```rust
{
    let writer_clone = writer.clone();
    let health = Arc::clone(&influx_healthy);
    let device_name = device.name.clone();
    tokio::spawn(async move {
        match writer_clone.write(&reading).await {
            Ok(()) => {
                // D-07: unhealthy → healthy transition
                if !health.load(Ordering::Relaxed) {
                    health.store(true, Ordering::Relaxed);
                    tracing::info!("InfluxDB connection restored");
                }
            }
            Err(e) => {
                // D-07: healthy → unhealthy transition (first failure logs WARN)
                // While unhealthy: silently drop per-write errors (no repeated WARN spam)
                if health.swap(false, Ordering::Relaxed) {
                    // Was healthy (true), now set to false — log the transition
                    tracing::warn!(
                        device = %device_name,
                        error = %e,
                        "InfluxDB write failed — suppressing further warnings until restored"
                    );
                }
            }
        }
    });
}
```

Key design points:
- `health.swap(false, Relaxed)` returns the previous value: if `true` (was healthy), log WARN; if `false` (already unhealthy), silently drop — this is the D-07 suppression behavior.
- `health.store(true, Relaxed)` on success after checking `!health.load(Relaxed)` — restores healthy state and logs INFO once.
- D-02: No semaphore, no bounded channel — unbounded spawns are safe (4GB RAM, 288MB used, each task holds ~6 f64 values + a name string).
- D-03: Out-of-order HTTP delivery is acceptable — timestamps set at Modbus read time.
- D-05: Spawned task owns `writer_clone`, `reading` (moved), and `health` (Arc clone).
